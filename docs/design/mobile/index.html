CrowdShield for Android — screen designs

The citizen companion app from TechNova Problem Statement 1, designed as a native mobile experience rather than a port of the web page. Every colour, font and risk label below is taken from the live web app (index.css, riskUi.js) so the two clients read as one product. Copy is the real STRINGS table, which already ships in English, Hindi and Odia.

Flow 1 · First run — language before anything else

Multilingual is a functional requirement, not a setting. A pilgrim who cannot read English must never see an English screen first, so the language choice comes before sign-in and is remembered on the device. Sign-in reuses the same cookie session and roles as the web backend.

Flow 2 · Home — the situation, at a glance

One screen answering "am I safe, and what do I do". The headline state is the largest thing on it, because someone reads this while walking. Below it: what the control room has announced, what is rising nearby, and the two actions that matter. Three states shown, since the honest "unmeasured" case is as common as the others and must not look like "all clear".

Flow 3 · Map and navigation

On the web this is a card in a scrolling page. On a phone the map is the screen — full-bleed, with a bottom sheet that carries the decision. The route drawn is the same one the backend computes for the web client, from the same imported OpenStreetMap network, so the app and the control room can never send someone down different roads.

Flow 4 · Reporting, alerts and the assistant

The two directions information travels. Out of the phone: SOS and structured reports, which are how the control room learns about things no sensor can see. Into the phone: push alerts that arrive whether or not the app is open, and the AI companion — already grounded in the citizen brief, with its answers rendered as real formatted text.

What is deliberately not here

No authority console. Problem Statement 1 scopes mobile to "a companion mobile application for citizens", and the Round 2 deliverable is "a working mobile app and a reporting portal" — so the control room stays on the web, where a 27-inch map and a 5-panel command centre belong. If you want on-ground marshals to have a phone view, that is a separate, much smaller surface (acknowledge alert, confirm a zone by eye, close a gate) and I would design it as its own flow rather than shrinking the console.

No web navbar or sidebar. Bottom tabs replace them. The web citizen page is one long scroll holding situation, alerts, destinations, exit, SOS and reporting; on a phone that buries the SOS button below three folds, which is the one thing that must always be one tap away.
